# Rules for the AI

1. Read all `.md` files before coding. If files conflict, `04_CONTENT.md` wins for content, `02_DESIGN_SYSTEM.md` for visuals.
2. Never invent business facts (address, hours, reviews, staff, prices). Use `[TBC]` placeholders.
3. Do not copy Boho's text, images or logo. Imitate patterns, not assets.
4. Work one phase at a time. End each phase with: what changed, files touched, how to run, what to review, open questions.
5. Prefer small, typed, reusable components. No hard-coded colors or prices.
6. Keep dependencies minimal; justify any new one.
7. Ask before large decisions (switching stack, adding pages, changing the design direction).
8. If a requirement is ambiguous, ask one concise question rather than guessing.
9. Never remove `prefers-reduced-motion` support or accessibility features to make something look better.
10. Final report must list: all [TBC] items still open, assumptions made, and anything that deviates from the reference.
